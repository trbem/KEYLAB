# KEYLAB｜网页视觉设计稿与 Codex 前端开发提示词

> 项目定位：机械键盘 DIY 在线组装平台。第一版聚焦 75% 配列，采用 3D
> 爆炸式组装；支持配件替换、兼容性提示、配置清单，以及自营商品与第三方商品混合购买。

## 1. 视觉总方向

-   **视觉关键词**：深色科技感、精密硬件、客制化、沉浸式
    3D、紫色强调色。
-   **主背景**：接近黑蓝色（如 `#090B14`）；卡片使用深蓝灰（如
    `#151827`）。
-   **强调色**：紫色/蓝紫渐变（如 `#8B5CF6`、`#A78BFA`）。
-   **文字**：主文字 `#F5F5FA`，次级文字 `#9AA1B5`。
-   **布局**：桌面端优先；顶部导航 + 内容区；工作台采用左侧零件栏、中间
    3D 场景、右侧配置栏。
-   **交互原则**：3D
    视图是主角，商品卡片和配置面板为辅助；避免大量装饰抢占模型空间。

## 2. 页面视觉规格

### A. 首页 `/`

**目标**：让用户 5 秒内理解"可以在线设计并组装自己的机械键盘"。

页面结构： 1. 顶部导航：KEYLAB Logo、首页、DIY
组装、配件商城、职业选手方案、我的配置、搜索、登录。 2. Hero
区：左侧标题"打造属于你的机械键盘"，副标题"3D 在线组装 · 海量配件 ·
职业方案复刻"；主按钮"开始 DIY 组装"，次按钮"观看演示"。 3.
右侧主视觉：75% 键盘 3D
爆炸模型，键帽、轴体、定位板、PCB、填充棉、外壳沿 Z 轴分层悬浮。 4.
功能卖点：3D 拆解组装、海量配件、职业选手方案、兼容性检测。 5.
推荐入口：热门配件、热门配置、快速开始模板。

**关键行为**： - "开始 DIY 组装"进入 `/builder`。 -
"观看演示"播放预设爆炸/合体动画。 -
首页展示的商品和方案必须由数据驱动，不能硬编码成无法维护的静态内容。

### B. 3D 组装工作台 `/builder`

**目标**：完成完整的 75% 键盘选配和组装体验。

桌面布局： - 左侧（约 220--260px）：配件分类与可选商品卡片。 -
中间（自适应）：Three.js 3D 场景，默认展示爆炸视图。 - 右侧（约
280--320px）：当前配置、兼容性状态、价格汇总和操作按钮。 -
顶部工具条：探索模式/拆解模式、重置视角、爆炸程度滑杆、显示/隐藏标注。

配件分类： - PCB 主板 - 定位板 - 轴体 - 键帽 - 外壳 -
填充棉（底棉、夹心棉、轴下垫） - 卫星轴及其他配件

交互规则： 1. 用户可以点击商品卡片，或将商品拖入 3D 场景。 2.
拖拽时只允许放入对应组件槽位；合法槽位高亮。 3.
松开后进行兼容性检查；兼容则吸附到预设安装坐标，不兼容则拒绝安装并解释原因。
4. 零件替换后，3D 模型、清单、价格和进度同步更新。 5.
支持旋转、缩放、平移、重置视角、爆炸程度调节。 6.
"探索模式"展示完整键盘；"拆解模式"沿 Z 轴分层分离。 7.
移动端暂不要求完整拖拽，可先采用点击选择 + 自动吸附。

**重要实现约束**：不要让用户任意改变零件最终安装坐标。拖拽只负责选择目标槽位，安装位置由模型配置中的
anchor/transform 决定，以保证结构准确。

### C. 配件商城 `/parts`

**目标**：让用户按类别、规格和预算找到配件。

页面结构： - 顶部标题与搜索框。 -
分类标签：全部、PCB、定位板、轴体、键帽、外壳、填充棉、其他。 -
筛选区：配列、材质、连接方式、热插拔、价格区间、品牌。 -
商品网格：商品图、名称、规格摘要、价格、销售渠道、加入
DIY/加入购物车。 -
商品详情抽屉或详情页：多角度图片、规格、兼容配件、库存/购买渠道。

商品卡片应明确标记： - **平台自营**：站内加入购物车。 -
**第三方商品**：显示商家与外部购买按钮，点击后跳转商家页面。 -
不要把外部跳转伪装成站内结算。

### D. 配置清单 `/cart` 或工作台右侧抽屉

**目标**：把当前 DIY 方案变成可执行的采购清单。

展示内容： - 已选配件、缩略图、规格、数量、单价、小计。 -
未完成槽位和兼容性提醒。 - 自营商品小计、第三方商品估算小计、总预算。 -
保存配置、复制分享链接（可在后续阶段实现）、加入自营购物车、逐项跳转外部购买。

混合购买规则： - 自营商品：加入站内购物车；MVP
可先做模拟购物车，不接真实支付。 - 第三方商品：打开已验证的商家商品
URL。 -
价格需要标注更新时间；第三方价格可能变化，应提示以商家页面为准。 -
购物清单不得把缺失配件或不兼容配件算作已完成。

## 3. 3D 模型与参考素材整理

### 建议优先使用的模型格式

-   首选 GLB / glTF。
-   每个可替换零件独立建模、独立命名，避免整把键盘只有一个合并网格。
-   建议统一模型原点、单位、朝向和安装坐标。
-   模型应包含可读的 mesh 名称，例如
    `case_bottom`、`pcb`、`plate`、`switch_01`、`keycap_01`。
-   对重复键帽和轴体可使用实例化渲染优化性能。

### 图片素材使用建议

-   首页：使用高质量成品键盘或爆炸视图作为主视觉。
-   工作台：尽量使用真实可操作的 GLB 模型，不要用图片假装 3D。
-   配件商城：每类商品使用统一角度、统一背景的独立商品图。
-   参考图片仅用于设计方向；正式上线时应使用自有渲染、获得授权的图片或供应商提供的商品素材。

## 4. 数据结构建议

### Part（配件）

``` ts
type Part = {
  id: string;
  name: string;
  category: "pcb" | "plate" | "switch" | "keycap" | "case" | "foam" | "stabilizer" | "other";
  description?: string;
  imageUrl?: string;
  modelUrl?: string; // GLB
  price: number;
  currency: "CNY";
  salesChannel: "self" | "external";
  merchantName?: string;
  productUrl?: string;
  specs: Record<string, string | number | boolean>;
  compatibleWith?: string[];
  status: "active" | "draft" | "unavailable";
};
```

### BuildConfig（组装配置）

``` ts
type BuildConfig = {
  id: string;
  name: string;
  layout: "75";
  selectedParts: Partial<Record<Part["category"], string[]>>;
  createdAt: string;
  updatedAt: string;
};
```

### CompatibilityRule（兼容规则）

``` ts
type CompatibilityRule = {
  id: string;
  sourceCategory: string;
  targetCategory: string;
  condition: Record<string, unknown>;
  severity: "error" | "warning" | "info";
  message: string;
};
```

MVP 可先使用本地 JSON
商品数据和规则，不急于接入真实数据库。兼容性规则应集中管理，避免散落在
UI 组件中。

------------------------------------------------------------------------

你是一名资深前端工程师和 Three.js 交互开发工程师。请在当前代码仓库中开发
KEYLAB，一个机械键盘 DIY 在线组装平台。

### 产品目标

构建一个深色科技风格的网站，用户可以在浏览器中通过 3D 爆炸视图组装一把
75% 配列机械键盘，选择
PCB、定位板、轴体、键帽、外壳、填充棉等配件，实时预览最终外观，查看兼容性和价格，并生成混合购买清单。

### 技术要求

-   Next.js App Router
-   React + TypeScript
-   Three.js + React Three Fiber
-   @react-three/drei
-   Zustand
-   Tailwind CSS
-   模型格式 GLB / glTF

如果仓库已经存在技术栈或代码规范，优先兼容现有工程，不要无理由重建项目。

### 设计要求

-   深色背景，紫色作为主要强调色。
-   页面简洁、精致，具有硬件产品工作台的感觉。
-   首页突出 3D 键盘爆炸视图。
-   工作台采用左侧配件栏、中间 3D 场景、右侧配置面板。
-   商品卡片展示图片、名称、规格、价格和购买渠道。
-   适配桌面端；窄屏下将侧栏改为抽屉或折叠面板。

### 必须实现的页面

1.  `/` 首页：产品介绍、3D 主视觉、开始 DIY 入口、功能卖点和推荐配件。
2.  `/builder` 3D
    组装工作台：模型展示、爆炸/合体、零件选择、拖拽吸附、兼容性提示、价格同步。
3.  `/parts` 配件商城：分类、筛选、商品卡片、加入 DIY、购买渠道标识。
4.  `/cart`
    配置清单：已选配件、缺失项、兼容状态、价格汇总、自营购物车和外部购买链接。

### 3D 工作台要求

-   优先实现可运行的程序化占位模型；没有可用 GLB 时，不得让页面空白。
-   键盘零件应分层组织：键帽、轴体、定位板、PCB、填充棉、外壳。
-   支持轨道旋转、缩放、平移和重置视角。
-   支持爆炸程度控制，零件沿 Z 轴分层移动。
-   支持探索模式和拆解模式。
-   点击配件卡片后，替换对应零件；如果实现拖拽，必须提供明确的合法槽位高亮和吸附反馈。
-   所有替换操作都应同步更新配置状态、价格和清单。
-   模型加载失败时展示友好错误状态和程序化模型回退。

### 兼容性要求

-   建立独立的 compatibility service。
-   至少检查配列、PCB 与外壳安装规格、PCB 与定位板孔位、轴体与 PCB
    插座类型、键帽与轴心规格。
-   兼容性结果分为 error、warning、info。
-   error 阻止安装；warning 允许继续但必须展示原因；info 作为说明。
-   不允许仅凭商品名称判断兼容性，使用结构化 specs 和规则数据。

### 混合购买要求

-   `salesChannel=self`：加入站内购物车。
-   `salesChannel=external`：打开商品 `productUrl`。
-   外部商品必须标记第三方来源，并提示最终价格以商家页面为准。
-   MVP 不接真实支付，不收集银行卡信息。

### 开发流程

请严格按以下顺序执行：

**阶段 0：检查项目** - 检查 package.json、目录结构、已有组件和依赖。 -
输出实施计划和潜在风险。 - 不要覆盖用户已有代码。

**阶段 1：基础页面** - 建立导航、全局主题、首页、商城、配置清单。 -
使用本地 mock 数据。 - 确保路由可访问。

**阶段 2：3D 场景** - 建立 KeyboardScene。 - 建立独立的零件组件。 -
实现程序化占位模型、爆炸视图和相机控制。

**阶段 3：配置状态** - 使用 Zustand
管理所选零件、模式、爆炸程度和总价。 - 实现零件选择、替换、移除和重置。

**阶段 4：拖拽与兼容性** - 实现拖拽目标和合法槽位提示。 -
实现自动吸附。 - 建立兼容性规则服务和错误提示。

**阶段 5：清单与购买** - 实现配置清单和价格汇总。 -
实现自营购物车与第三方外链。 - 外链使用真实配置 URL，不得编造商家链接。

**阶段 6：测试和优化** - 检查桌面端和窄屏布局。 -
检查模型加载失败回退。 -
检查无选择、部分选择、不兼容和价格缺失等边界状态。 - 修复
TypeScript、Lint 和运行错误。

### 工程质量要求

-   组件职责清晰，避免把所有逻辑写进单个页面。
-   3D 场景与普通 UI 分离。
-   商品数据、兼容性规则和 UI 分离。
-   关键交互有加载、成功、失败和空状态。
-   不要用静态截图冒充可交互 3D。
-   每个阶段完成后运行检查并汇报改动文件、运行命令、测试结果和未完成事项。
-   未经确认不要删除已有文件或引入不必要的大型依赖。

### MVP 验收标准

用户能够： 1. 打开首页并进入 DIY 工作台。 2. 看到一把 75% 键盘的 3D

PCB、定位板、轴体、键帽、外壳和填充棉。 5. 看到兼容性检查结果。 6.
看到配置清单和实时总价。 7. 将自营商品加入站内购物车。 8.
打开第三方商品购买链接。

## 7. 实施建议

第一周优先完成页面骨架和程序化 3D
模型；第二周完成零件替换、爆炸动画和配置状态；第三周完成兼容性、清单和混合购买；最后集中处理模型精度、性能和视觉细节。

不要把"职业选手真实配置库"、用户社区、支付和多配列支持放进首期关键路径。先把一把
75% 键盘从空配置到完整清单的体验做扎实。
