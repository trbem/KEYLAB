# 成品键盘目录与后续数据库映射

商城中的成品键盘来自本机 `local-data/keyboard-products.json`，不会自动写入 Supabase。源文件位于用户提供的迈从和 Wooting 数据目录；此目录及采集数据不随 Git 提交。运行下面的命令可以整理源文件，已有文件内容不同时会停止，避免覆盖人工编辑：

```powershell
node scripts/prepare-keyboards.mjs 'D:\26级音乐润之班\maicong-keyboards\out\maicong_全部键盘.csv' 'D:\26级音乐润之班\wooting-scrape\out\wooting_全部商品.csv' 'D:\26级音乐润之班\wooting-scrape\out\wooting_规格明细.csv'
```

当前数据包含迈从 32 款、Wooting 6 款成品键盘。UwU 是三键小键盘，不在本次范围。迈从其中 12 款为官方商城采集的参考起价，其余 20 款缺价为 `null`；Wooting 价格为 2026-11-09 中国站最低变体价。迈从资料及这批价格采集日期为 2026-11-12。价格为快照而非实时价格，实际以商家页面为准。图片和链接保留源文件中的 HTTPS 地址，不下载网页图片；公开发布前须核对素材使用范围。

已有本地目录可单独补充迈从的空价格，采集日期必须填写源资料真实日期：

```powershell
node scripts/prepare-keyboards.mjs --update-maicong-prices 'D:\26级音乐润之班\maicong-keyboards\out\maicong_全部键盘.csv' 2026-11-12
```

脚本按 `CMS_code` 匹配，修改前在 `local-data/` 创建备份；不同的已有价格、无效价格和缺失商品会报告冲突并保留原值。重复执行不会覆盖已有价格或其他手工修改。备份及数据均由 Git 忽略。

## 未来导入方案（尚未执行）

以下映射用于后续审阅，并非已经创建或导入远端数据：

| 本地字段 | 现有数据库候选位置 | 注意事项 |
| --- | --- | --- |
| `id`、`name`、`description` | `products.id`、`name`、`description` | 使用稳定的品牌前缀和来源 ID，冲突先报告，不覆盖已有商品。 |
| `kind: keyboard` | `categories.id`、`products.category_id` | 现有商品表可引用分类，但商城归一化器只认识组装槽位；未来须增加独立成品键盘类型和相应读取逻辑。 |
| `brand` | `brands`、`products.brand_id` | 先审查现有品牌 ID 和重名情况；不凭名称覆盖远端数据。 |
| `priceCents`、`currency` | `products.price_cents`、`currency` | 金额为整数分、缺价为 `null`；采集时的最低变体价应标注参考起价。 |
| `imageUrl`、`purchaseUrl` | `products.image_url`、`product_url` | 仅写有效 HTTPS；Wooting 官网资料地址与购买链接分开记录，不假设商品一定可购买。 |
| `sourceUrl`、`capturedAt`、`priceSource`、`priceCapturedAt`、`specs` | `product_specs.specs` JSON | 保留商品与价格来源、各自的采集时间和原始规格；采集时间不是人工核验时间，也不是兼容性证明。 |

远端导入前应先只读检查项目现有结构、数据与权限，并准备可审阅的映射和冲突报告；数据库表、分类或数据的变更需要依据当时的用户授权与项目规则执行。图片许可、价格及可购状态须另行核对；不要把价格或库存快照视为实时信息。
