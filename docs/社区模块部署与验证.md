# KEYLAB 社区模块：配置与验证

社区代码已实现，目标项目的数据库和存储尚未由本次开发修改。仅当实际应用迁移、配置登录并验证后，才能使用真实的跨设备社区；界面在服务不可用时显示错误，不会将本地演示冒充云端内容。

## 功能与数据

- 游客可浏览已发布的帖子和可见评论；邮箱登录后可以发布文字、可选设备清单和最多一张 JPG、PNG 或 WebP 图片（最大 5 MB），点赞、收藏、评论和举报。
- 管理员可以查看举报和对应内容，隐藏帖子或评论并标记举报已处理；普通用户无法自行成为管理员或隐藏内容。
- `community_posts`、`community_comments`、`community_likes`、`community_favorites`、`community_reports` 和 `community_moderators` 存储社区数据。图片在私有 `community-images` 存储桶中，按用户目录上传；公开帖子使用短期签名地址读取，隐藏后已有签名地址最多在有效期内仍可访问（当前为 120 秒）。
- 帖子、收藏和举报列表目前各最多读取 50 条，评论最多读取 100 条；未实现分页、作者编辑删除、发帖频率限制或云端内容自动审核。点赞和收藏状态仅对本人可见，不提供公开计数。公开测试前应准备内容管理和防刷方案。

## 目标项目启用前检查

1. 确认目标 Supabase 项目及环境，备份并检查其中是否已存在同名社区表、策略或 `community-images` 存储桶；迁移不会覆盖已有存储桶，同名冲突应先解决。不要对未知或有重要数据的数据库盲目执行。
2. 审阅 [社区迁移](../supabase/migrations/20261104085545_community.sql)，确认表、RLS、显式 GRANT、私有存储桶和 Storage 策略符合目标项目。该迁移独立于现有商品演示数据，真实远端表不会由前端自动创建。
3. 经项目负责人确认后，在目标项目的 Supabase SQL Editor 执行该迁移，或由有权限的人员通过经过审核的迁移流程执行。不要将 service-role key、数据库密码或访问令牌放进前端、日志、仓库或聊天。
4. 在 Supabase Auth 启用邮件登录，在允许重定向地址中加入实际访问地址的 `/community`，例如 `http://localhost:3000/community`；如果使用其他域名或 `127.0.0.1`，还需分别配置对应地址。实际发信依赖项目的邮件服务配置。
5. 登录后如需指定管理人员，由项目负责人通过受控的 SQL Editor 使用该账户的真实 UUID 添加 `community_moderators` 记录；不要授予普通用户写入该表的权限。先确认该邮箱属于正确账号，再执行：

```sql
insert into public.community_moderators (user_id)
select id from auth.users where email = '填写管理员登录邮箱'
on conflict (user_id) do nothing;
```

此语句在邮箱不存在时插入 0 行；确认账号和执行结果后，重新登录以显示“举报管理”。不在聊天中提供账号密码或密钥。

## 测试与限制

- 本地 `pnpm test` 使用 PGlite 模拟 Auth 和 Storage 表，验证社区 RLS、用户隔离、举报关联和管理员操作；它不是远端 Supabase 或真实 Storage 服务测试。
- `pnpm test:e2e` 中的社区交互测试拦截网络请求并使用模拟会话、图片和 API，不会写入真实数据库；无 Supabase URL 配置时该交互测试会跳过。
- 应用迁移后，用两个普通邮箱和一个管理员账号在目标环境验证：游客浏览、邮箱链接回跳、带图和无图发帖、点赞/收藏、评论、举报、隐藏后游客不可见、跨设备恢复以及图片访问权限。
- 若图片上传已完成但网络在发帖时中断，页面会提示发布结果不确定。请先刷新检查帖子，避免重复发布；管理人员可按实际情况检查并处理未被帖子使用的图片。
- 登录失败或表不可读时，核查 Data API 表暴露、GRANT 和 RLS、Auth 重定向地址、邮件服务与 Storage 权限；不要为了排错使用高权限密钥或关闭 RLS。
